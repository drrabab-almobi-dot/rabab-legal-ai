# 2. الخدمات ومسارات المستخدم

## 2.1 هيكل الخدمات المعتمد

```
الباحثة الذكية
        ↓ يغذي
الاستشارة العامة  ↔  الاستشارة القضائية وإدارة القضية
        ↓
العقود: صياغة · تحليل · استخراج بيانات
```

## 2.2 الاستشارة القانونية العامة

### الهدف

إعطاء المستخدم فهماً عملياً للمسألة دون تحويلها إلى تحليل خصومة أو استراتيجية تقاضٍ.

### المخرج المطلوب

- الحكم النظامي واسم النظام ورقم المادة عند توفر مرجع متحقق.
- الحقوق والالتزامات.
- المسارات والخطوات العملية.
- الجهة المختصة.
- المستندات المطلوبة.
- المواعيد والمدد النظامية.
- التنبيهات والحدود.
- إخلاء المسؤولية.

### المحظور

لا نقاط قوة أو ضعف، ولا دفوع، ولا تحليل خصم، ولا تقدير مركز قانوني، ولا نسبة نجاح.

### مسار المستخدم

1. يختار الاستشارة القانونية.
2. يحدد الدولة.
3. يشرح الوقائع.
4. يجيب عن أسئلة الاستيضاح داخل الجلسة.
5. يحصل على نتيجة موثقة قابلة للحفظ.
6. يستلم النتيجة بصيغة Word أو PDF وفق صلاحية الباقة.
7. يطلب تأكيد المحامية د. رباب المعبي، عند الحاجة، من خلال إجراء مستقل يحدد نطاق المراجعة ومرفقاتها.
8. يُعرض عليه الانتقال إلى المسار القضائي أو المراجعة البشرية عند الحاجة.

## 2.3 الاستشارة القضائية وإدارة القضية

### المخرج المطلوب

- التكييف القانوني.
- الاختصاص وعبء الإثبات.
- الأدلة ونقاط القوة والضعف بأسانيدها.
- تحليل دفوع الطرف الآخر.
- الدفوع المقترحة.
- السوابق والمبادئ.
- المخاطر والمواعيد.
- استراتيجية إجرائية بصياغة غير ضامنة للنتيجة.

### إدارة القضية

- ملف قضية مستقل لكل مستخدم.
- ذاكرة تراكمية للجلسات والمذكرات.
- تقرير لكل جلسة.
- تحديث الملخص بدل إعادة تحليل الملف كاملاً.
- تحرير أنواع المذكرات المعتمدة كمسودات.
- دراسة الأحكام والتحقق من طريق ومدة الاعتراض.

## 2.4 العقود

### صياغة العقود

- تحديد الدولة والإطار القانوني.
- اختيار نوع العقد.
- إدخال الوقائع والشروط.
- تحديد مدة التسوية الودية.
- اختيار **آلية النزاع** بشكل مختصر بين **قضاء** و**تحكيم**.
- تفاصيل مركز التحكيم وعدد المحكّمين لا تظهر إلا عند اختيار التحكيم.
- إخراج مسودة واضحة تحتاج مراجعة قانونية.

### تحليل العقود

- استخراج نص العقد مرة واحدة وحفظه.
- جدول مخاطر وتوصيات.
- تمييز البنود الحساسة.
- فحص التوافق مع الاختصاص.
- عدم عرض استنتاج بلا سند أو دون توضيح أنه تحليل مساعد.

### استخراج البيانات

- استخراج الأطراف والتواريخ والقيم والالتزامات والجزاءات.
- التعامل مع PDF وDOCX وTXT والملفات المصورة عند توفر OCR.
- إظهار حالة الاستخراج وجودته.
- تمكين المستفيد من طلب تأكيد المحامية على المسودة أو التحليل دون مشاركة أي ملف إضافي خارج ما اختاره للطلب.
- تسليم المسودة والتحليل بصيغة Word قابلة للتنزيل وفق الصلاحية.

## 2.5 الباحث القانوني الذكي

### مصادر البحث

- الأنظمة واللوائح والقرارات.
- التعاميم القضائية والتنظيمية.
- الأحكام والسوابق.
- المدونات والمبادئ القضائية.
- قاعدة المعرفة المعتمدة.
- البحث الحي عند تفعيله.

### بطاقة النتيجة

كل نتيجة ينبغي أن تعرض:

- نوع المصدر.
- الرقم والتاريخ.
- الجهة المصدرة.
- الدولة والاختصاص.
- درجة المحكمة للأحكام.
- حالة السريان.
- درجة الارتباط.
- أوجه التشابه والاختلاف.
- رابط المصدر الرسمي إن وجد.

### السرية والمرفقات وطلب التأكيد

تقبل كل خدمة نشطة الملفات ذات الصلة من المستفيد ضمن صيغ وحجم معلنين. تربط المنصة الملف بصاحبه وجلسة أو تشغيل الخدمة، ولا تستخدمه في التدريب أو التسويق أو لإفادة مستخدم آخر. يستطيع المستفيد من كل نتيجة أو خدمة بدء طلب **تأكيد المحامية**، فتشارك للمراجعة المهنية فقط الوقائع والنتيجة والمراجع والمرفقات التي حددها صراحة، مع سجل حالة للطلب. لا يظهر اسم المحامية أو بيانات التواصل داخل النص القانوني المصدّر؛ تظهر هوية الإشراف وخيار التأكيد في واجهة الخدمة المخصصة لذلك.

## 2.6 التوسع المستقبلي للخدمات

تضاف الخدمة الجديدة كوحدة مستقلة بحالة مخططة، ولا تدخل اختيار المستخدم أو توجيه الموضوعات أو الباقات قبل اعتمادها. يجب أن تتضمن الوحدة الجديدة تعريف الاختصاص، ونموذج الإدخال، وسياسة رفع الملفات، وقواعد المصادر والتحقق، وقالب Word، ومسار تأكيد المحامية، واختبارات الأمان والجودة. تعد خدمة **توزيع الميراث** مثالاً لخدمة مستقبلية تحتاج منهجاً مستقلاً لحصر البيانات والورثة والتحفظات قبل تفعيلها.

## 2.7 الحساب والباقات والدفع

1. تصفح الخدمات والباقات.
2. إنشاء حساب وتحقق البريد عند الحاجة.
3. اختيار الباقة أو الخدمة.
4. تطبيق الحصة والحد اليومي من الخادم.
5. تنفيذ الدفع والتحقق الذري.
6. تفعيل الاشتراك والفاتورة.
7. عرض الاستهلاك والنتائج السابقة.

## 2.8 لوحة الإدارة

- المستخدمون والحسابات.
- الباقات والاشتراكات والكوبونات.
- المدفوعات والفواتير.
- الاستشارات والجلسات.
- قاعدة المعرفة والمصادر.
- جودة النص وإعادة الاستخراج.
- إعدادات إظهار الأقسام.
- سجل التدقيق والتنبيهات.
- حالة المزامنة والوظائف الخلفية.

## 2.9 مسارات تطبيق الجوال

### المستخدم الجديد

1. يفتح التطبيق ويرى الخدمات العامة.
2. يختار الخدمة والدولة.
3. عند بدء خدمة محمية ينتقل إلى تسجيل الدخول.
4. يعود تلقائياً إلى نفس الخدمة بعد نجاح الدخول.

### المستخدم المسجل

1. يرى حالة الاشتراك والحصة.
2. يبدأ استشارة أو بحثاً أو خدمة عقود.
3. يرفع ملفاً مع بيان نوعه وحالة استخراجه.
4. يتابع الرد أو حالة المعالجة.
5. يحفظ النتيجة ويعود إليها من السجل.
6. يتلقى التنبيه عند اكتمال المعالجة أو قرب انتهاء الاشتراك.

### قواعد الجوال

- لا يختلف تعريف الصلاحية أو خصم الحصة بين الويب والجوال.
- لا تُرسل الأسرار أو مفاتيح الخدمات إلى التطبيق.
- تُعرض الأخطاء وحالات انقطاع الشبكة بوضوح مع إعادة المحاولة الآمنة.
- تُحترم RTL وإمكانية الوصول وأحجام الشاشات الصغيرة.

## 2.10 Mobile application flows

### New user

1. Open the app and browse public services.
2. Choose a service and jurisdiction.
3. Sign in when a protected action starts.
4. Return to the same service after successful authentication.

### Signed-in user

1. View subscription and quota status.
2. Start a consultation, search, or contract service.
3. Upload a file with its type and extraction status.
4. Follow the response or processing state.
5. Save the result and reopen it from history.
6. Receive notifications for completed work or subscription warnings.

### Mobile rules

- Authorization and quota deduction are identical on web and mobile.
- Secrets and provider keys never ship in the app.
- Network and retry states are explicit and safe.
- RTL, accessibility, and small-screen layouts are required.

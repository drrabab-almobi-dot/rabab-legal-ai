# 3. المراحل وخارطة الطريق

هذه خارطة تنفيذ مرتبة بالأولوية، وليست وعداً زمنياً. لا تبدأ مرحلة قبل اجتياز شروط قبول المرحلة السابقة.

## المرحلة 0 — الحوكمة وتثبيت الأساس

### الهدف

توحيد المرجع، حماية الهوية، ومنع التغييرات التي توسع النطاق بلا اعتماد.

### الأعمال

- اعتماد `replit.md` كمرجع أعلى.
- إبقاء الويب أولوية.
- تثبيت الخدمات والمسميات ومسارات الرجوع.
- عدم تعديل `index.css` أو الألوان أو الخطوط.
- تحديد صلاحية كل خدمة وباقة على الخادم.
- إنشاء نسخة احتياطية قبل التغييرات الجوهرية.

### معيار القبول

لا يوجد تعارض بين الواجهة والخادم ووثيقة المواصفات، ولا تُقبل ميزة جديدة بلا نطاق ومعيار نجاح.

## المرحلة 1 — قاعدة المعرفة والمصادر الرسمية

### الهدف

بناء طبقة معرفية يمكن الوثوق بها وتغذية كل الخدمات منها.

### الأعمال

- استيراد PDF/TXT/DOCX والروابط.
- تنظيف النص العربي ومعالجة RTL والكشيدة.
- تقسيم المستندات إلى مقاطع مع بيانات المصدر.
- إنشاء embeddings وربطها بالوثيقة الأم.
- تصنيف المصدر والدولة والجهة والتاريخ وحالة السريان.
- دعم المدونات القضائية والتعاميم والأحكام والأنظمة.
- بوابة مراجعة بشرية قبل اعتماد المصدر.
- مراقبة الوثائق الفاسدة وإعادة الاستخراج.

### معيار القبول

كل وثيقة معتمدة قابلة للتتبع من النتيجة إلى المصدر الأم، ولا تدخل وثيقة منخفضة الجودة القاعدة المعتمدة دون حالة واضحة.

## المرحلة 2 — البحث والتحقق

### الهدف

إرجاع مصادر أدق مع منع الاستشهاد غير المتحقق.

### الأعمال

- بحث هجين حرفي ودلالي.
- إعادة ترتيب النتائج بـ RRF.
- تمرير الاختصاص والدولة إلى الاسترجاع.
- دعم الاستعلامات المتعددة والبحث التنظيمي.
- التحقق البرمجي من وجود النص والمرجع.
- عرض درجة الارتباط والتنبيه عند ضعف المصدر.
- حفظ نتيجة البحث وإعادة فتحها لاحقاً.

### معيار القبول

لا تُعرض مادة أو حكم على أنه موثق إلا إذا اجتاز التحقق، ويظهر اختلاف الدولة أو حالة السريان للمستخدم بوضوح.

## المرحلة 3 — الخدمات الأساسية

### الهدف

استكمال المسارات التي يدفع المستخدم من أجلها.

### الأعمال

- الاستشارة العامة وحوار الاستيضاح.
- الاستشارة القضائية وإدارة القضية.
- تحرير المذكرات ودراسة الأحكام.
- صياغة العقود وتحليلها واستخراج البيانات.
- آلية النزاع في صياغة العقود: قضاء/تحكيم باختيار مختصر.
- حفظ الجلسات والنتائج والمصادر.
- تصدير PDF وWord حسب الصلاحيات.

### معيار القبول

كل خدمة تسلك مسارها الصحيح، لا تختلط مستويات الاستشارة، ولا تُخصم الحصة قبل نجاح المخرج.

## المرحلة 4 — الحساب والاشتراكات

### الهدف

تحويل الاستخدام إلى تجربة مدفوعة قابلة للقياس والاسترداد.

### الأعمال

- المصادقة والجلسات واستعادة الحساب.
- التحقق من البريد.
- الباقات والحصص والحد اليومي.
- الدفع والتحقق من العملية بشكل ذري.
- استرداد الاشتراك المدفوع غير المفعل.
- الفواتير والكوبونات.
- تنبيهات الحصص وانتهاء الاشتراك.

### معيار القبول

لا يستطيع المستخدم تجاوز صلاحية الخادم، ولا تُفقد الحصة عند خطأ API، ولا يتكرر تفعيل الدفع أو إرسال التنبيه.

## المرحلة 5 — الإدارة والتشغيل

### الهدف

تمكين إدارة المحتوى والجودة دون تعديل مباشر للبيانات الحساسة.

### الأعمال

- إدارة المصادر وحالاتها.
- مراقبة جودة النص.
- إعادة الاستخراج وإعادة الفهرسة.
- إدارة المستخدمين والباقات والمدفوعات.
- سجل عمليات غير قابل للحذف العرضي.
- إعدادات إظهار الأقسام.
- تقارير الاستهلاك ومؤشرات القاعدة.
- جدولة المهام والتنبيهات مع حماية من التكرار.

### معيار القبول

كل إجراء إداري حساس قابل للتتبع، وأي فشل في مهمة مجدولة لا يوقف تسجيل الدخول أو الخدمات الأساسية.

## المرحلة 6 — المزامنة والبحث المستمر

### الهدف

تغذية قاعدة المعرفة من المصادر المعتمدة بطريقة قابلة للاستئناف والمراجعة.

### الأعمال

- استكمال MTProto بحساب مستخدم حقيقي عند الموافقة.
- checkpoint واستئناف السحب الكامل.
- منع تنزيل الملف نفسه عبر SHA-256.
- لوحة تقدم تفصيلية.
- حساب التكلفة قبل تشغيل المعالجة.
- موافقة بشرية قبل إدخال الوثائق.
- تصنيف متعدد المراحل مع درجات ثقة.
- متابعة الجديد بعد ثبات السحب الكامل.

### معيار القبول

يمكن إيقاف العملية واستئنافها دون فقدان التقدم، ولا تُفهرس وثيقة غير معتمدة، وتظهر التكلفة قبل أي تشغيل مدفوع.

## المرحلة 7 — بوابة الجودة والإطلاق

### الهدف

الانتقال من بيئة التطوير إلى إطلاق آمن بعد موافقة صريحة.

### الأعمال

- اختبار المسارات العامة والمحمية.
- اختبار الدول والاختصاصات.
- اختبار الملفات العربية والمصورة.
- اختبار الحصص والدفع والاسترداد.
- فحص أمني وتدقيق تبعيات.
- مراجعة النصوص القانونية وإخلاء المسؤولية.
- اختبار الثيمات الثلاثة دون تعديل الهوية.
- اختبار الجوال بعد ثبات الويب.
- تجهيز خطة مراقبة واسترداد.

### معيار القبول

لا أخطاء حرجة، ولا مسار دفع أو مصادقة مكسور، ولا بيانات مستخدم مكشوفة، وموافقة صاحبة المنصة تسبق أي نشر إنتاجي.

## المرحلة 8 — تطبيق الجوال

### الهدف

تقديم تجربة مستخدم جوال كاملة تعتمد على نفس API وقواعد الصلاحيات والبيانات، بعد ثبات الويب.

### الأعمال

- تثبيت عقود API المشتركة مع الويب.
- تسجيل الدخول واستعادة الجلسة والعودة إلى المسار المطلوب.
- شاشة الخدمات والباقات والاستهلاك.
- الاستشارة والمحادثة والبحث القانوني.
- رفع الملفات ومتابعة حالة الاستخراج.
- السجل والحفظ والتصدير أو المشاركة حسب الصلاحية.
- إشعارات الاشتراك والحصة والاستشارة.
- حالات انقطاع الشبكة وإعادة المحاولة الآمنة.
- اختبار Android وiOS وأحجام الشاشات وإمكانية الوصول.

### معيار القبول

تعمل المسارات الأساسية على الجوال دون اختلاف في الصلاحيات أو الحصص أو النتائج عن الويب، ولا تُخزّن أسرار الخدمات في التطبيق، وتُجتاز اختبارات المصادقة ورفع الملفات والعودة من الدفع.

## Mobile delivery order

### Phase 8 — Mobile application

**Goal:** Deliver a complete end-user mobile experience on the same API, authorization rules, and data model after the web platform is stable.

**Work:** stabilize shared API contracts; authentication and return paths; services, plans, and quota screens; consultation and legal search; uploads and extraction status; history and export/share permissions; notifications; offline/network states; Android/iOS/accessibility testing.

**Acceptance:** Mobile and web enforce the same permissions, quotas, and result rules; no provider secrets are bundled; authentication, uploads, payment return paths, and core service flows pass on supported devices.

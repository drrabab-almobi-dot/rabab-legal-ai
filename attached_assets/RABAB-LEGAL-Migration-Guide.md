# RABAB LEGAL AI — دليل نقل المشروع

تاريخ إعداد الحزمة: 20 أغسطس 2026

## 1. محتوى الحزمة

هذه الحزمة تنقل الشيفرة المصدرية والإعدادات القابلة لإعادة البناء، ولا تنقل الأسرار أو بيانات الإنتاج تلقائياً.

تشمل:

- واجهة الويب: `artifacts/rabab-legal`
- خادم API: `artifacts/api-server`
- تطبيق الجوال: `artifacts/rabab-mobile`
- مكتبات قاعدة البيانات ومواصفات API: `lib`
- السكربتات المساعدة: `scripts`
- ملفات المشروع العامة: `package.json` و`pnpm-workspace.yaml` و`pnpm-lock.yaml` و`replit.md`
- الأصول المرفوعة الموجودة داخل `attached_assets`

مستبعدة عمداً لأسباب أمنية وحجمية:

- `node_modules`
- مجلدات `dist` وملفات البناء المؤقتة
- `.git`
- `.agents` و`.local` وملفات سجلات الوكلاء
- أي ملف `.env` أو ملف يحتوي على أسرار
- جلسة Telegram، لأنها بيانات اعتماد حساسة ويجب نقلها بقناة آمنة منفصلة أو إعادة تسجيلها

## 2. المتطلبات

- Node.js 24 أو إصدار متوافق مع المشروع
- pnpm
- PostgreSQL
- نطاق أو عنوان عام للواجهة وخادم API
- تخزين ملفات دائم إذا كانت البيئة الجديدة لا توفر تخزيناً محلياً دائماً

## 3. التثبيت المحلي

من جذر المشروع:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm run typecheck
```

لتشغيل الواجهة:

```bash
pnpm --filter @workspace/rabab-legal run dev
```

لتشغيل خادم API:

```bash
pnpm --filter @workspace/api-server run dev
```

لتشغيل تطبيق الجوال:

```bash
pnpm --filter @workspace/rabab-mobile run dev
```

## 4. متغيرات البيئة والأسرار

يجب إدخال القيم في مدير أسرار البيئة الجديدة، وليس داخل الملفات أو Git. لا تنسخ القيم من سجل المحادثة.

### أساسية

- `DATABASE_URL`
- `SESSION_SECRET`
- `PORT`
- `NODE_ENV`
- `APP_URL` أو `SITE_URL` أو `FRONTEND_URL` بحسب طريقة النشر

### الذكاء الاصطناعي والبحث

- `OPENAI_API_KEY`
- `TAVILY_API_KEY`

### الدفع

- `MOYASAR_PUBLISHABLE_KEY`
- `MOYASAR_SECRET_KEY`

### البريد

- `SMTP_USER`
- `SMTP_PASS`
- `SMTP_FROM`

### WhatsApp

- `TWILIO_ACCOUNT_SID`
- `TWILIO_AUTH_TOKEN`
- `TWILIO_WHATSAPP_FROM`

### Telegram

- `TELEGRAM_API_ID`
- `TELEGRAM_API_HASH`
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_ADMIN_ID`

قبل التشغيل الإنتاجي يجب التحقق من أن كل مزود يستخدم بيانات اعتماد البيئة الجديدة، وأن Bot Telegram لا يعمل في بيئتين في الوقت نفسه.

## 5. نقل قاعدة البيانات

لا تتضمن الحزمة نسخة من قاعدة بيانات الإنتاج. انقليها بخطوة مستقلة ومراجعة يدوية:

1. خذي نسخة احتياطية مشفرة من قاعدة الإنتاج.
2. أنشئي قاعدة PostgreSQL جديدة.
3. استوردي النسخة إلى البيئة الجديدة.
4. راجعي الجداول التي تحتوي على جلسات المستخدمين، الاشتراكات، المدفوعات، الرسائل، وملفات المعرفة.
5. طبقي أي migrations لازمة بعد مقارنة schema، ولا تستخدمي أمر دفع schema عشوائياً على قاعدة الإنتاج.
6. اختبري تسجيل الدخول، الاشتراكات، الحصص، الدفع، والاستشارات قبل تحويل النطاق.

الجداول الحساسة وظيفياً تشمل، بحسب النسخة الحالية من المشروع: المستخدمين، الجلسات، الاشتراكات، المدفوعات، الفواتير، الاستشارات، رسائل الاستشارات، المستندات القانونية، المقاطع المسترجعة، وسجلات الإشعارات.

## 6. الملفات والأصول

إذا كانت ملفات المستخدمين أو قاعدة المعرفة محفوظة في Object Storage أو مزود خارجي، فيجب نقلها منفصلاً عن Git وعن هذا الأرشيف. راجعي:

- صلاحيات القراءة والكتابة
- الروابط المؤقتة
- أسماء الحاويات أو المسارات
- سياسة الاحتفاظ والحذف
- عدم جعل الملفات القانونية عامة بالخطأ

## 7. ترتيب الإطلاق المقترح

1. إنشاء البيئة الجديدة وإضافة الأسرار.
2. تثبيت الحزم وتشغيل فحص TypeScript.
3. نقل قاعدة البيانات وملفات Object Storage.
4. تشغيل API على منفذ `PORT` الصحيح.
5. فحص `/api/healthz` وتسجيل الدخول.
6. تشغيل الواجهة وربطها بنفس مسار API.
7. اختبار الدفع في وضع الاختبار قبل الإنتاج.
8. اختبار رفع PDF وWord والصور واستخراج النص.
9. اختبار البحث القانوني، الاستشارات، الحصص، الإشعارات، والتصدير.
10. تشغيل Telegram في بيئة واحدة فقط.
11. تحويل DNS بعد نجاح الاختبارات.
12. إبقاء البيئة القديمة متاحة للرجوع المؤقت، دون تشغيل مهام مجدولة أو بوتات مكررة.

## 8. قائمة اختبار ما قبل تحويل النطاق

- [ ] الصفحة الرئيسية والصفحات العربية تعمل باتجاه RTL.
- [ ] التسجيل وتسجيل الدخول وتسجيل الخروج تعمل.
- [ ] الجلسات محفوظة عبر HTTPS.
- [ ] استرجاع كلمة المرور يعمل عبر البريد.
- [ ] الاشتراك الفردي واشتراك المنشآت يعملان.
- [ ] الحصص لا تُخصم عند فشل التحليل.
- [ ] الدفع والـ callback والـ webhook موثقة ومختبرة.
- [ ] البحث لا يكرر طلبات Tavily بلا حاجة.
- [ ] النص المستخرج من الملف يظهر للمراجعة قبل التحليل.
- [ ] ملفات العملاء لا تظهر لمستخدم آخر.
- [ ] قاعدة المعرفة لا تستخدم مصادر محظورة أو مخفية.
- [ ] سجلات الأخطاء لا تطبع الأسرار أو محتوى الملفات.
- [ ] إشعارات البريد وWhatsApp تعمل عند الحاجة.
- [ ] Telegram يعمل في بيئة واحدة فقط.
- [ ] النسخ الاحتياطي والاسترجاع مجربان.

## 9. ملاحظات أمنية مهمة

- لا تضع أي قيمة سرية في هذا الملف أو في مستودع عام.
- أبطلي مفاتيح البيئة القديمة إذا كان النقل نهائياً.
- غيّري `SESSION_SECRET` إذا كانت الجلسات القديمة يجب أن تُبطل.
- أعدي ربط Webhooks بالدومين الجديد، خصوصاً الدفع والبريد وWhatsApp.
- لا تنقلي جلسة Telegram داخل ملف ZIP؛ استخدمي إعادة تسجيل آمنة.
- لا تنقلي قاعدة الإنتاج إلى بيئة اختبار دون سياسة إخفاء للبيانات الشخصية.

## 10. حدود هذه الحزمة

هذه الحزمة تنقل الشيفرة والتعليمات، لكنها لا تنفذ تلقائياً:

- إنشاء الحسابات لدى مزودي الدفع أو البريد أو الذكاء الاصطناعي
- نقل ملكية النطاق
- نقل قاعدة بيانات الإنتاج
- نقل Object Storage
- إعادة تفعيل Webhooks
- إصدار شهادات HTTPS
- التحقق التجاري من حساب Moyasar أو Twilio

بعد اختيار المنصة الجديدة، يجب إعداد ملحق خاص بها يحدد أوامر النشر، المنافذ، إعدادات DNS، وجدولة المهام.
